# intTransfer CLI 1.0.0

Клиент нового E2EE-протокола сервера intTransfer 1.0.0. Совместим с веб-клиентом:
файлы можно загрузить через CLI и скачать в браузере, и наоборот.

## Установка

Нужен Python 3.10+; сервер для запуска клиента устанавливать не нужно.
Зависимости: `requests`, `cryptography`. `tqdm` и `requests_toolbelt` не нужны.

```bash
python -m pip install -r cli-requirements.txt
python cli.py --help
```

Если скачан только `cli.py`:

```bash
python -m pip install requests cryptography
```

## Загрузка

Без пароля, хранение один день:

```bash
python cli.py --action upload --server https://transfer.example.com --file ./archive.zip --time 1d
```

С паролем, который будет запрошен без отображения символов:

```bash
python cli.py -a upload -s https://transfer.example.com --file ./archive.zip -t 6h -p
```

Поддерживаются `1h`–`168h`, `1d`–`7d`; по умолчанию — `7d`. Старые сроки
`10m`/`30m` недоступны. Пароль защищает ключ криптографически и не отправляется
серверу. Допускается старый синтаксис `--password текст`, но такой пароль может
оказаться в истории команд или списке процессов; интерактивный `-p` удобнее.
Пароль получателю нужно передать отдельно.

Готовая полная ссылка выводится в stdout. Статус передачи и ошибки — в stderr.
Срок хранения отсчитывает сервер от создания передачи. При повторе команды
готовая непросроченная ссылка выводится снова; для новой передачи нужен `--new`:

```bash
python cli.py -a upload -s https://transfer.example.com --file ./archive.zip -t 1h --new
```

## Скачивание

Используйте полную новую ссылку, обязательно в кавычках:

```bash
python cli.py -a download --url 'https://transfer.example.com/d/ID#ПОЛНЫЙ_ФРАГМЕНТ' -o ./received.zip
```

`--file-id` работает как синоним `--url`. Если ссылка защищена паролем, клиент
запросит его автоматически. `--server` при полной ссылке не нужен. Если он
указан, адрес должен совпадать с адресом ссылки.

Одного ID файла недостаточно. Можно указать ID и ключ-фрагмент отдельно:

```bash
python cli.py -a download -s https://transfer.example.com --file-id ID --key 'ФРАГМЕНТ_ПОСЛЕ_РЕШЁТКИ' -o ./received.zip
```

Без `--output` используется безопасное имя из расшифрованного манифеста.
`--output` также может указывать существующий каталог. Клиент не использует
пути из полученного имени файла, например `../file`.
Существующий файл не перезаписывается. Чтобы заменить его **после** успешной
проверки скачанных данных, явно укажите `--overwrite`.

## Продолжение после обрыва

Повторите ту же команду: клиент запросит подтверждённые блоки на сервере и
продолжит с недостающих. Исходный файл должен остаться доступным и неизменным.
При возобновлении сохраняются первоначальные пароль и срок; новые `-p` и `-t`
не переопределяют уже созданную передачу. Для другого содержимого нужен `--new`.

Состояние по умолчанию: `~/.cache/inttransfer-cli/`. В нём находятся токен
загрузки, ключ и один ожидающий подтверждения зашифрованный блок. На POSIX
новые каталоги создаются с правами 700, файлы — 600. В Windows доступ зависит
от ACL профиля пользователя. Не публикуйте файлы состояния и не переносите их
в общий каталог. Во время работы одна передача блокируется от параллельного
запуска другим процессом с тем же путём состояния.

При загрузке состояние сохраняется атомарно до отправки HTTP-запроса.
Если ответ потерялся, блок не шифруется повторно: используется сохранённый
шифротекст. После успешной загрузки из состояния удаляются незашифрованный ключ AES
и токен записи, остаётся готовая ссылка. Для ссылки без пароля её фрагмент
содержит ключ, поэтому готовое состояние тоже нужно хранить приватно.

При скачивании рядом с файлом назначения создаётся скрытый временный
`.inttransfer-....part` с уже расшифрованными блоками. Файл получает права 600
на POSIX. Готовый файл появляется только после проверки всех блоков и размера.
После обрыва временный файл сохраняется: уже записанные блоки перепроверяются,
повреждённый или незавершённый хвост скачивается повторно. Поэтому файл целиком
в памяти не собирается. Нужны свободное место на диске и файловая система,
поддерживающая hard links для атомарного сохранения без перезаписи.

Для своего пути состояния используйте `--state ./private/upload-state.json`.
Каждой передаче нужен свой путь; не используйте разные пути состояния для
одновременной записи в один и тот же файл назначения. Чтобы забыть передачу,
после завершения удалите соответствующий JSON. Чтобы отказаться от незавершённого
скачивания, удалите его JSON и временный `.part`. Серверный файл останется до
истечения срока хранения.

## Сеть и TLS

Сетевые ошибки, HTTP 429 и временные HTTP 5xx повторяются с увеличивающейся
задержкой, по умолчанию пять раз. Количество задаётся `--retries 0`–`20`.
После исчерпания повторов состояние остаётся для следующего запуска.
HTTP 507 (хранилище заполнено) и постоянные ошибки не повторяются автоматически.
Перенаправления запрещены: указывайте конечный HTTPS-адрес сервера.

TLS проверяется по умолчанию. Старый `--insecure` сохранён для явного отключения
проверки сертификата. HTTP разрешён для localhost; для других адресов нужно
явное `--allow-http`. Сквозное шифрование не заменяет защиту HTTPS.

## Проверки

Проверены обе стороны совместимости с фактическим `web/crypto.js`, пароль с
Unicode, пустой файл, повтор загрузки после потерянного подтверждения,
возобновление скачивания, обнаружение повреждённого локального блока и запрет
неявной перезаписи результата. Выполнение на Windows отдельно не проверялось.

Для запуска всех тестов проекта установите серверные и клиентские зависимости,
pytest и Node.js 22+:

```bash
python -m pip install -r requirements.txt -r cli-requirements.txt pytest
python -m pytest -q tests
node --test tests/crypto.test.js
```
